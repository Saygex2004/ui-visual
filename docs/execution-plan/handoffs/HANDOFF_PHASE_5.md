## 2. Notes, observations, implementation details

- **The automatic same-session archive move (task 6) collided with an existing Phase-4 fixture assumption, and the fix rippled into two files I didn't originally plan to touch.** Fixture listing `1001` (Campania/Napoli) has `data_vendita: "2020-01-01"` — deliberately, permanently in the past (clearly seeded in an earlier phase anticipating this exact feature). Once "Aggiorna alla data odierna" runs automatically on load, `1001` **always** moves out of Red Zone's live Principali table into the Archivio, on every single page load, forever. This silently broke two of Phase 4's own `dashboard-browse.spec.ts` assertions (Red Zone Principali count 2→1; Archivio count 2→3) the moment this phase's session-archive logic went live — caught only by actually running the full e2e suite, not by reasoning about it in isolation. Fixed by updating those two assertions with a comment explaining why, cross-referencing the new `session-archive.spec.ts`. It also meant the originally-planned "Napoli OMI error-doc" e2e case (task 2's price panel) is untestable at the browser level — `1001` is the *only* row with `comune === "Napoli"`, so once it auto-archives, "Napoli" never appears as a drill-down option in a live cluster table at all. Dropped that specific e2e assertion in favour of the still-fully-covered "absent doc" case (Caserta) plus the pre-existing unit-level coverage of the error-doc branch in `omi.test.ts` — DATA_MODEL.md §4 explicitly says the UI must never distinguish the two cases anyway, so this isn't a coverage gap, just a redistribution of *where* the error-doc case is verified.
- **Playwright's dialog handling: `Promise.all([page.waitForEvent('dialog'), button.click()])` can deadlock when the click itself synchronously triggers a blocking `window.alert`/`confirm`.** `click()` genuinely hung past the 30s test timeout mid-action ("performing click action" never completing) in the first `session-archive.spec.ts` attempt. Fixed with the canonical, documented-safe idiom instead: register `page.once('dialog', handler)` **before** the click (a true listener, not a promise composed alongside the action), let the handler call `dialog.accept()`/`dismiss()` itself, then just `await` the click normally — the registered listener is what lets the click's own internal completion wait resolve at all. Factored into a small `clickExpectingDialog` helper in `session-archive.spec.ts` since it's needed three times in one test.
- **`Intl.NumberFormat('it-IT', {style:'currency', maximumFractionDigits:0})` does not insert a thousands separator for 4-digit values on this Node/Chromium's bundled ICU** (`2800 €`, not `2.800 €` — confirmed both by the actual e2e failure and by reproducing it directly in `node -e`), though it does for 6-digit values (`250.000 €`). Not a product bug — it's the browser's own locale data, and the app correctly defers to `Intl` rather than hand-rolling grouping. Fixed by making the e2e assertions tolerant of either (`/2\.?800/`) rather than asserting one specific grouping — more robust across whatever ICU version a given CI/dev machine happens to ship, not just a one-off fixup.
- **A real filename-casing collision on macOS's default case-insensitive-but-case-preserving filesystem**: `drilldown.ts` (planned name for the pure helpers) and `DrillDown.tsx` (the component) differ only in case, and TypeScript refuses this outright (`TS1149`) since the two would collide on Windows/default-macOS regardless of extension. Renamed the helpers file to `drilldownHelpers.ts`. Worth remembering for any future pure-logic-file-beside-same-named-component pattern.
- **Playwright runs spec files in alphabetical-by-path order, and this codebase has a real (if implicit) ordering contract on it.** `auth-flow.spec.ts` is the one file that performs the actual bootstrap-admin/forced-password-change dance and rotates the shared admin's password as a side effect; every other spec file uses a resilient `loginAsAdmin` helper (`e2e/helpers.ts`, extracted this phase from `dashboard-browse.spec.ts`'s previously-inline, now-shared copy — needed by 4 more new files) specifically because it doesn't know or care whether `auth-flow.spec.ts` already ran. Two of this phase's new files (`admin-categories.spec.ts`, `archive-session.spec.ts`) sorted alphabetically *before* `auth-flow`, which broke `auth-flow.spec.ts`'s own bootstrap-specific assertion (it got the "already rotated" password state instead of the fresh one) the first time the full suite ran. Renamed to `categories-admin.spec.ts` and `session-archive.spec.ts` — sorts after `auth-flow`, contract restored. Any future e2e file must keep this in mind: nothing may sort before `auth-flow.spec.ts` unless it's equally self-contained about which password is active.
- **DOMAIN_RULES.md §9's "Capital municipality selected: the same panel semantics, for that comune's document" is easy to miss on a first read of UI §3.3 alone** — §3.3's own prose only says "when a province is selected." Cross-checking DOMAIN_RULES (the more precise, implementation-facing document) before writing `OmiPanel.tsx` avoided shipping a panel that silently didn't work for the capital-selection path.
- **`blocco_index` (the snapshot) records which clusters a block spans but not which bucket within a target cluster** — by design (recorded already in the approved plan, confirmed correct in implementation): `findBucketForBlocco` searches the target cluster's actual rows at jump time. This is cheap (cluster sizes here are tens of rows, not thousands) and avoids a second precomputed index that could drift from the first.
- No conflicts with the Specifications beyond the two explicitly recorded above (the third-onward-link addition in task 10, and the e2e Napoli-case redistribution in this section's first point) — both within `00_OVERVIEW.md` §5's compliance rule (recorded here, chosen in the spirit of the actual requirement).
