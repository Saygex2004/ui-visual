## 2. Notes, observations, implementation details

- **PrimeReact 11's `Drawer` role override, verified by tracing compiled source three layers deep** (`@primereact/headless/drawer` → `primereact/drawer/popup` → `@primeuix/utils/mergeprops`), not assumed: `useDrawer`'s hook defaults `popupProps.role` to `'complementary'`. Passing `role="dialog"` as a plain JSX prop on `<DrawerPopup>` works because any prop not in the sub-component's own `defaultProps` (`as`, `motionProps`) is bucketed into an `attrs` object, which is merged in **after** — and therefore overrides — the hook's own `popupProps` in the final `mergeProps(popupProps, ..., attrs, ...)` call; `mergeProps` does last-write-wins for plain attribute keys like `role`. Confirmed in the real, running app via the manual verification pass (§1.11): `role="dialog"` and `aria-modal="true"` both present on the actual DOM node.
- **`useMutation`'s dispatch to `isPending: true` is not synchronous with the click handler that calls `.mutate()`** — `onMutate` itself is `async` and does `await queryClient.cancelQueries(...)` before any state change most callers would expect to observe. A first pass at `RatingControl.test.tsx` asserted `expect(mockFn).toHaveBeenCalledWith(...)` and `.disabled === true` immediately after `fireEvent.click(...)`, with zero calls recorded — not a bug in the component, just wrong test timing. Fixed by wrapping every post-click assertion in `waitFor(...)` (React Testing Library, auto-retrying), the same principle `ratings-collaboration.spec.ts` already applies for the cross-actor poll wait, just at a much smaller timescale.
- **The TanStack Router `<Link search={(prev) => ...}>` callback form does not reliably typecheck inside a component that isn't itself tied to a specific route** (`useParams`/`useSearch({from: ...})`) — `tsc` can't infer `prev`'s type against the target route's schema from a generic component like `DataTable.tsx` or `RelatedLots.tsx`, and rejects it the moment the target route's search schema has fields that are `.catch()`-defaulted but still *required* in the parsed output type (`cluster`/`tab`/`dir`). Fixed everywhere it came up (`DataTable.tsx`, `RelatedLots.tsx`, and by extension `ClusterSection.tsx`/`ArchiveSection.tsx`, which now thread `search={search}` down) by accepting an explicit, already-correctly-typed `search: AreaSearch`/`ListingSearch` prop from a caller that already has one, and building the target as a literal object (`search={{...search, pannello: 'dettagli'}}`), never a callback. Worth remembering for any future component in this shape.
- **`AreaView.tsx` was missing `<Outlet />`** (§1.8) — caught by actually reading the file end-to-end while planning, not by assuming a Drawer-based rewrite of the placeholder component would be sufficient on its own. A useful reminder that a route-level rendering gap can silently sit underneath a component that otherwise looks complete.
- **`ratings-collaboration.spec.ts` is the slowest file in the e2e suite (28s) by design, not by accident** — it deliberately waits out one real `POLL_CADENCES_MS.ratings` (20s) cycle twice (set, then clear) with auto-retrying assertions (`expect(locator).toHaveAttribute(..., {timeout: 25_000})`), rather than mocking the clock or stubbing the poll. `test.setTimeout(120_000)` on that one test accommodates it. If the suite's total runtime ever becomes a problem, this is the file to look at first — but note it caught real, correct poll behaviour on the very first run, not a flake.
- **`seedContent()` (used by `PVPDASH_SEED=1`, i.e. every e2e run) deliberately never loads `ratings.json`/`listing_activity.json`/`assignment_index.json`** — only `seedAll()` (used by `pnpm test:integration`) does, because those fixtures reference `user-1`/`user-admin-1`, and `seedContent()` composes with the server's own account bootstrap/reset step by design (see `seed/lib.ts`'s own doc comment, predates this phase). This means every e2e listing starts genuinely unrated with zero activity history — `ratings-collaboration.spec.ts` relies on this and creates all its own state at runtime rather than depending on any pre-seeded rating.
